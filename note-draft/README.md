# note-auto-draft — noteの下書きを自動で作るツール

記事のテキストと画像をフォルダにまとめておくと、コマンド1つで **note.com の「下書き」まで**自動で作ります。
**公開ボタンは自動で押しません。** 最後は必ず、あなたがnoteの画面で確認してから手で公開します。

> なぜ下書きまでか：誤公開・重複投稿・画像抜け・ログイン切れの事故を防ぐためです。

---

## 使うために必要なもの

- Node.js が入ったPC（mac）
- Google Chrome / Chromium が動くPC
- note のアカウント（自分でログインできること）
- 入稿したい記事フォルダ（`article.md` ＋ 画像）

（インストール等は導入時に済ませてあります。増やす場合のみ `npm install` します）

---

## いちばん最初に1回だけ：ログイン

```
npm run login
```

- ブラウザが開きます。**あなたが手動で note にログイン**してください。
- ログインを検知すると自動で保存し、ブラウザが閉じます（Enter入力は不要）。
- 「実際にエディタを開けるか」で確認するので、本当にログインできたときだけ保存します。
- パスワードは保存しません。ログイン済みの状態だけを `storage/note-auth.json` に保存します。

一度やれば、しばらくは再ログイン不要です（ログインが切れたら、もう一度これを実行）。

---

## 記事フォルダの作り方

`articles/` の中に、記事ごとのフォルダを作ります。

```
articles/
  my-article/
    article.md        ← 本文（下記の書き方）
    thumbnail.png     ← サムネイル（見出し画像）／任意
    images/
      fig1.png        ← 本文中に入れる画像
      fig2.png
```

`article.md` の書き方：

```markdown
---
title: 記事のタイトル
thumbnail: ./thumbnail.png
tags:
  - AI
  - 副業
---

本文をふつうに書きます。

![説明](./images/fig1.png)

## 見出し

続きの本文。

![説明](./images/fig2.png)
```

- 画像は `![説明](パス)` と書いた場所に入ります。
- 対応画像：`.png` `.jpg` `.jpeg` `.webp`（`.gif` `.svg` などは非対応）

## 実行の流れ

### 1. 事前チェック（noteには触りません）

```
npm run dry-run -- articles/my-article
```

タイトル・本文文字数・画像の枚数・サムネイルの有無を確認します。ここでエラーが出たら直します。

### 2. 下書きを作る

```
npm run draft -- articles/my-article --headed
```

- **必ず画面ありモード（--headed）で実行してください。** noteのエディタは画面なし(headless)だと読み込めません。
- ブラウザが開いて、noteの新規投稿画面に入力していきます。
- タイトル → サムネイル（見出し画像）→ 本文 → 本文画像 → **下書き保存** の順です。
- 終わると「下書きURL」を表示します。noteの画面で中身を確認してください。

> 注意：`npm run` に渡す引数は `--` を1回だけ付けます（`-- articles/... --headed`）。`-- ... -- --headed` のように `--` を2回付けるとエラーになります。

うまくいかないときは、画面を残して調べられます：

```
npm run draft -- articles/my-article --headed --pause-on-error
```

### 3. 公開

**このツールは公開しません。** note の画面で内容を確認し、問題なければ **あなたが手で公開**してください。

## 困ったとき

- まず環境を点検： `npm run doctor`
- 失敗時は `screenshots/` に画面が、`logs/` に手順のログが残ります（本文全文やパスワードは記録しません）。
- 「タイトル欄が見つからない」等が出たら、noteの画面が変わった可能性があります。`src/selectors.ts` を直せば直ります（変更箇所はこのファイルに集約しています）。

---

## 制限（MVPで割り切っていること）

- **画面ありモード必須**：noteエディタはheadlessだと読み込めないため、`--headed` で実行します。
- **見出し・太字は再現しません**：本文はプレーンテキストで入ります（`##` や `**` の記号は落とします）。見出しは通常の段落として入ります。
- **画像は本文中の正しい位置に入ります**：本文テキストを全部入れてから、各画像を「直前の段落」を目印にその位置へ差し込みます（`--no-inline-images` を付けると末尾にまとめます）。まれに目印が見つからない画像は末尾に入るので、その場合は下書き画面でドラッグ移動してください。
- **1回実行するごとに新しい下書きが1件作られます**：同じ記事で複数回試すと下書きが増えます。不要なものは note の下書き一覧から手動で削除してください（このツールは削除しません）。
- 自動公開・予約投稿・既存記事の編集/削除・複数アカウント・CAPTCHA/2段階認証の自動突破は**やりません**。

## 画面が変わって動かなくなったら

noteのエディタ更新でボタンや入力欄の場所が変わると失敗することがあります。`src/selectors.ts` に操作対象を集約しているので、そこを直せば復旧できます。実画面の構造を調べる補助スクリプト `scripts/inspect-editor.mjs` で、現在のボタン名やセレクタを確認できます。

詳しい安全方針は [SECURITY.md](./SECURITY.md) を見てください。
