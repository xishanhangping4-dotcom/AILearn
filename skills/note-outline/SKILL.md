# note-outline — note記事の構成を作る

記事の骨組みを設計する工程。**必ず一度止まって承認を得てから本文（note-write）へ進む**。

## 参照

- あなたの設定：`~/note-kit/profile.md`（読者・テーマ・CTAはここから読む）

## 入力

- テーマ（何について書くか）
- 狙い（読者に何を持ち帰ってほしいか）
- 誘導先（設定ファイルのCTA。空欄なら誘導なし）

## 記事の型

- **タイトル**：具体的な数字＋読者の得られるもの＋テーマ
  - 例「◯◯を△△する3つの手順」「1日15分で〜する方法」
- **リード（書き出し）**：この4ステップで組む
  1. 問題提示 — 読者の"あるある"な悩みから入る
  2. 解決イメージ — 読み終えたあとの姿
  3. 読むメリット — この記事で何が分かるか
  4. 安心感 — 「今日ぜんぶやらなくていい」「専門知識はいりません」
- **本文 H2**：4〜7本。行動が想像できる言い回しにする
- **各H2内の H3**：疑問解決型（「なぜ〜か」「〜の中身はこれ」）
  - **自己開示エピソードを1つ挟む**（設定ファイルの「自己開示に使えるエピソード」から）
- **逃げ道**：各セクションに「まずここだけでOK」「今日のゴール」など、ハードルを下げる一言
- **締め**：振り返り → 次の一歩 → CTA（設定ファイルの導線。空欄なら省く）

## 設計の手順

1. テーマから、読者が抱く悩み・つまずきを5〜10個書き出す
2. 悩みに答える論点を選び、H2を4〜7本に整理する（見出しだけ拾って話が通る形に）
3. 各H2に、入れる要素をメモする（具体例・数字・手順・自己開示・逃げ道）
4. リード方針（4ステップ）とタイトル案を2〜3個出す
5. 締めの導線を確定する
6. 全体の文字数配分を置く（設定ファイルの目安文字数に合わせる）

## 承認ゲート

構成案を提示し、最後に必ずこう聞く。

> この構成で本文を書いてよいですか？（直したい見出しがあれば教えてください）

修正指示があれば直して再提示する。承認が出たら **note-write** へ進む。

## 出力フォーマット

```
タイトル案：…（2〜3個。おすすめに印をつける）
狙い／誘導先：…
リード方針：問題提示→解決イメージ→メリット→安心感（1行ずつ）

## H2（見出し）｜入れる要素：具体例/数字/自己開示/逃げ道
### H3（疑問解決型）
### H3
（H2ごとに繰り返し）

## まとめ＋CTA：振り返り→次の一歩→導線
想定文字数：◯◯字
```

## 注意

- 承認前に本文へ進まない
- 参考にした記事の表現をそのまま写さない。型は真似ても、言葉は独自にする
- 読者が初心者なら、専門用語には必ず言い換えを添える前提で設計する
