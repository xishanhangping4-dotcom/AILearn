# note-auto — noteを通しで1本作る

note-outline（構成）→ note-write（本文）→ note-image（図解）を順につないで、**下書き1本を仕上げる**司令塔。

- **構成で1回だけ止まる**：方向がずれたまま最後まで書くと手戻りが大きいため
- **note本体には投稿しない**：入稿は最後にコマンドを案内する。公開は必ず手動
- **設定ファイルがすべての土台**：`~/note-kit/profile.md` を最初に必ず読む

> 各工程のルールは、その職人スキルを読んで従うこと（内容をここにコピーしない）。

## 参照

| 用途 | 場所 |
|---|---|
| あなたの設定（文体・読者・CTA） | `~/note-kit/profile.md` |
| 構成の型 | `~/.claude/skills/note-outline/SKILL.md` |
| 文体ルール・採点ループ | `~/.claude/skills/note-write/SKILL.md` |
| 図解の作り方 | `~/.claude/skills/note-image/SKILL.md` |
| 作業ディレクトリ | `~/note-kit/note-draft` |

## 手順

### 0. 設定を読む（必ず最初）

`~/note-kit/profile.md` を読む。

- ファイルが見つからないときは、そこで止まってユーザーに場所を聞く
- 大部分が空欄のときは、「設定を埋めるともっとあなたらしい記事になります」と一言添えて、分かる範囲で進める

### 1. ネタを決める

ユーザーがテーマを言っていれば**それを使う**（この工程は飛ばす）。

言っていなければ、設定ファイルの「発信のテーマ」と「読者の悩み」から候補を5本出し、ユーザーに選んでもらう。

### 2. 構成を作る（**ここで1回止まる**）

`note-outline/SKILL.md` の型と手順に従って構成を組む。

- タイトル案を2〜3個出し、おすすめを1つ示す
- 最後に必ず聞く → 「この構成で本文を書いてよいですか？」
- 直しの指示があれば反映して、もう一度見せる

> 「止めずに一気に書いて」と言われたときは、この確認を飛ばして本文へ進んでよい。

### 3. 本文を書く

`note-write/SKILL.md` の文体ルール・事実の裏取り・**採点ループ（総合95点以上）**に従う。

- 文体は設定ファイルの「文章のトーン」と「サンプル文」に合わせる
- 事実（ツールの機能・数値・料金など）は断定する前にWeb検索で裏を取る
- 何度直しても95点に届かないときは、無理に通さず理由を報告して止まる

### 4. 図解を作る（3〜4枚）

`note-image/SKILL.md` に従う。

- 作るのは**図解だけ**（HTML/CSS → PNG）。追加の料金はかからない
- 人物イラストは別途OpenAIのAPIキーが必要（1枚3〜15円）。設定がなければ作らず、図解だけで進める
- できたPNGは**必ず目を通して**、文字の重なり・見切れがないか確かめる
- 1枚も作れなくても本文は完成させ、その旨を最後に伝える

### 5. 記事フォルダに書き出す

`~/note-kit/note-draft/articles/<記事名>/` を作る（記事名は英小文字とハイフン）。

```markdown
---
title: 決めたタイトル
tags:
  - タグ1
  - タグ2
---

本文…

![図解の説明](./images/fig1.png)
```

- 画像は該当する見出しの直後に入れる
- 使える画像は `.png` `.jpg` `.jpeg` `.webp`

### 6. Notionに保存する（設定がある場合だけ）

設定ファイルの「保存先のデータベースID」が**空欄なら、この工程は飛ばす**。

書いてあるときは、保存前に一度だけ確認してから保存する（外部への書き込みのため）。

### 7. 報告する

- 実際の文字数と最終スコア
- 作った図解の枚数
- 記事フォルダの場所
- noteに下書きを入れるコマンド（**実行はユーザーが手動**）：

```bash
cd ~/note-kit/note-draft && npm run draft -- articles/<記事名> --headed
```

> このコマンドは下書きを作るだけで、公開はしない。初回、またはログインが切れていたら先に `npm run login`。

---

## 注意

- 構成にない話を足して文字数を稼がない
- 参考にした記事の表現をそのまま写さない。型は真似ても、言葉は自分のものにする
- 事実の裏が取れないことは書かない。書くなら「〜の場合があります」と弱める
- 誇大な表現（絶対／必ず／誰でも／100％ 等）は使わない
